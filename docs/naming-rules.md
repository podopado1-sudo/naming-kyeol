# 작명규칙 연구 및 적용 (2026-06-23)

전통 한국 작명규칙을 웹에서 조사·정리하고, 본 프로젝트 철학(**미학 우선, 미신 배제**)에
부합하는 것만 선별해 엔진에 반영한 기록.

## 불용한자 정책 — 채택 / 거부

작명규칙의 "불용한자"는 두 갈래이며, 본 프로젝트는 **명확히 구분**한다.

### ✅ 채택 — 불용한자(부정적 의미)
음(音)·훈(訓)의 뜻이 부적합한 글자. 좋은 이름의 합리적 기준이므로 배제한다.
- 죽음·재앙: 死亡喪屍厄禍凶 …
- 병·고통: 病疾痛苦患 …
- 악·범죄·형벌: 惡邪魔鬼罪犯刑獄賊盜殺 …
- 천함·열등·가난: 愚拙劣卑賤奴乞貧困 …
- 더러움·추함·부정감정: 醜汚臭怨恨怒哀 …
- 불쾌한 짐승: 犬狗豚鼠蛇蟲 …

구현: `HanjaData.ForbiddenNameHanjaSet` + `IsForbiddenNameHanja()`,
`NamePoolEngine`의 한자 풀에서 배제. (해당 발음에 좋은 대체 한자가 있으면 발음은 유지됨.)

### ❌ 거부 — 불길한자(미신)
明(밝을)·仁(어질)·德(덕)·榮(영화)·東·泰·光 등을 **"단명·고난·재난"**으로 보는 류.
- 출처마다 목록이 제각각이고 작명가가 임의로 정함(권위 있는 표준 없음).
- 사주·성명학 **미신**이며, 明·仁·德은 오히려 **최고의 이름 글자**.
- 본 프로젝트 철학("사주로 이름을 만들지 않는다 / 미학 우선")과 **정면 충돌** → 채택하지 않음.

## 결론
1. 전통 작명규칙의 **합리적 부분은 이미 엔진에 구현**돼 있음(이번에 검증).
2. 빠져 있던 **불용한자(부정적 의미) 배제**를 추가 — 좋은 이름의 안전장치.
3. **불길한자 미신은 의도적으로 배제** — 이것이 본 서비스의 차별점이자 철학.
4. 작명규칙은 "맞는 이름(궁합·길흉)"을 다루지, "예쁜 이름(미감)"을 만들어주지 않음.
   창의·미감 품질은 별도 과제(큐레이션/데이터)로 다룬다.
