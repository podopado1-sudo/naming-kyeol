## 1. 범위

### Phase 1 — 백엔드 이벤트 수집 + 집계 API (이번 작업)
- 추천 요청이 들어올 때마다 카테고리/엔드포인트 사용 이벤트를 DB에 기록
- 집계 조회 API 1개

### Phase 2 — 프론트 탭 클릭 이벤트 (이번 작업, 소규모)
- `/search` 결과 화면에서 사용자가 카테고리 탭을 클릭할 때 이벤트 전송
- smart 요청은 모든 카테고리를 한 번에 생성하므로, **사용자가 실제로 본 탭**은
  프론트 이벤트로만 알 수 있음 — 이게 엔진 존폐 판단의 핵심 데이터

### 제외 (이번 작업 아님)
- 대시보드 UI, IP/세션 추적, A/B 테스트

## 2. 데이터 모델

`Domain/Models/UsageEvent.cs` (신규):

```csharp
namespace NameForm.Domain.Models;

/// <summary>사용량 이벤트 (append-only, PII 없음)</summary>
public class UsageEvent
{
    public long Id { get; set; }
    public string EventType { get; set; } = "";  // "endpoint" | "tab_view"
    public string Key { get; set; } = "";        // "smart", "creative", "twin" 등
    public DateTime CreatedAt { get; set; }      // UTC
}
```

- **PII 금지**: 성씨, 이름, 생년월일, IP, User-Agent 어떤 것도 저장하지 않는다.
- 집계는 조회 시 GROUP BY (저장 시 upsert 경합 없음 — 트래픽 낮아 row 누적으로 충분).
- `AppDbContext`에 DbSet 추가 + OnModelCreating: HasKey(Id), EventType MaxLength(30),
  Key MaxLength(40), CreatedAt 인덱스 (`entity.HasIndex(e => e.CreatedAt)`).

## 3. ⚠️ DB 마이그레이션 함정 — 가장 중요한 부분

이 프로젝트는 EF Migrations를 쓰지 않고 `EnsureCreated()`를 쓴다.
**`EnsureCreated()`는 DB가 이미 존재하면 새 테이블을 만들어주지 않는다.**
운영 DB(Supabase PostgreSQL)에는 이미 Recommendations 등이 있으므로,
그냥 배포하면 UsageEvents 테이블이 없어서 런타임 에러가 난다.

해결: `Program.cs`의 기존 "DB 스키마 초기화" 블록(177행 근처, Recommendations
존재 검증 + 강제 생성 fallback 패턴) **뒤에** 다음을 추가:

```csharp
// UsageEvents 테이블 — 기존 DB에 추가되는 테이블이므로 EnsureCreated가 못 만듦.
// CREATE TABLE IF NOT EXISTS로 멱등 생성 (SQLite/PostgreSQL 모두 지원 문법)
try
{
    var isNpgsql = dbContext.Database.ProviderName?.Contains("Npgsql") == true;
    var createUsageTable = isNpgsql
        ? """
          CREATE TABLE IF NOT EXISTS "UsageEvents" (
              "Id" BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
              "EventType" VARCHAR(30) NOT NULL,
              "Key" VARCHAR(40) NOT NULL,
              "CreatedAt" TIMESTAMP NOT NULL
          );
          CREATE INDEX IF NOT EXISTS "IX_UsageEvents_CreatedAt" ON "UsageEvents" ("CreatedAt");
          """
        : """
          CREATE TABLE IF NOT EXISTS "UsageEvents" (
              "Id" INTEGER PRIMARY KEY AUTOINCREMENT,
              "EventType" TEXT NOT NULL,
              "Key" TEXT NOT NULL,
              "CreatedAt" TEXT NOT NULL
          );
          CREATE INDEX IF NOT EXISTS "IX_UsageEvents_CreatedAt" ON "UsageEvents" ("CreatedAt");
          """;
    dbContext.Database.ExecuteSqlRaw(createUsageTable);
    initLogger.LogInformation("UsageEvents 테이블 확인/생성 완료");
}
catch (Exception ex)
{
    initLogger.LogWarning("UsageEvents 테이블 생성 실패 — 사용량 집계 비활성: {Error}", ex.Message);
}
```

참고: Npgsql legacy timestamp behavior가 켜져 있으므로(`Program.cs` 최상단)
`DateTime.UtcNow` 저장에 Kind 문제 없음.

## 4. 수집 서비스

`Application/Services/IUsageTracker.cs` (신규):

```csharp
public interface IUsageTracker
{
    /// <summary>이벤트 기록. 실패해도 예외를 던지지 않는다 (추천 요청을 막으면 안 됨).</summary>
    Task TrackAsync(string eventType, string key);
}
```

`Infrastructure/Repositories/EfUsageTracker.cs` (신규): AppDbContext 주입,
Add + SaveChangesAsync, **전체를 try/catch로 감싸 LogWarning만** (절대 throw 금지).

DI 등록 (`Program.cs`): `builder.Services.AddScoped<IUsageTracker, EfUsageTracker>();`

테스트에서는 `NoopUsageTracker`(아무것도 안 함)를 만들어 주입
— 기존 테스트 생성자(예: `RecommendationQualityTests`)는 수정하지 않아도 되도록,
**컨트롤러에만 주입**하고 서비스 계층(SmartRecommendationService 등)에는 주입하지 않는다.

## 6. API (신규 `Api/Controllers/UsageController.cs`)

### POST `/api/v1/usage/event` — 프론트 탭 클릭용
- Body: `{ "eventType": "tab_view", "key": "creative" }`
- **서버측 화이트리스트 필수** (쓰레기 데이터 방지):
  - eventType: `tab_view`만 허용
  - key: `standard, pure-korean, three-syllable, creative, parent-based, required-char, dual-name, twin, rare-surname` 만 허용
  - 불일치 → 400
- 응답: 204 NoContent
- Rate limit: 전역 정책(60/분)이면 충분 — `expensive` 정책 불필요

### GET `/api/v1/usage/summary?days=30`
- days 기본 30, 최대 365 (`[Range]` 검증)
- 응답: `[{ "eventType": "endpoint", "key": "smart", "count": 123 }, ...]`
  (기간 내 GROUP BY EventType, Key, count 내림차순)
- 공개 집계라 인증 불필요 (개인정보 없음)

## 7. 프론트엔드 (Phase 2)

1. `frontend/src/lib/api.ts`에 `trackTabView(key: string)` 추가:
   - `navigator.sendBeacon(`${API_URL}/usage/event`, blob)` 사용 (실패 무시, await 불필요)
   - sendBeacon 미지원 시 fire-and-forget fetch (`keepalive: true`)
2. `/search` 결과 화면의 카테고리 탭 클릭 핸들러에서 호출.
   - 탭 컴포넌트 위치는 `frontend/src/components/results/` 안에서 카테고리 탭을
     렌더링하는 컴포넌트를 찾아서 적용 (탭 전환 onClick에 한 줄)
   - **같은 탭 중복 전송 방지**: 컴포넌트 state로 세션 내 탭당 1회만 전송
3. 기본 선택 탭(standard)도 결과 로드 시 1회 전송 (분모 확보)
